8. TIMER / TASK STATE MACHINE
======================================================================

TASK STATES
TODO --> IN_PROGRESS --> COMPLETED
  |            |             |
  |            +--> TODO     +--> TODO (reopen action if supported)
  +--> CANCELLED (optional future state)

WORK SESSION STATES
[No session] --Start--> [RUNNING]
[RUNNING] --Pause--> [PAUSED]
[PAUSED] --Resume--> [RUNNING]
[RUNNING] --Finish--> [FINISHED]
[PAUSED] --Finish--> [FINISHED]

TIMER RULES
1. At most one WorkSession may be RUNNING globally unless the product deliberately changes that rule.
2. Start stores startedAt = current epoch milliseconds and accumulatedMs = 0 for a new session.
3. Pause adds (now - startedAt) to accumulatedMs, clears startedAt, and sets status PAUSED.
4. Resume sets startedAt = now and status RUNNING; accumulatedMs is retained.
5. Finish adds the final active interval only if status was RUNNING, records endedAt = now, clears startedAt, and sets FINISHED.
6. A paused session's displayed duration is accumulatedMs.
7. A running session's displayed duration is accumulatedMs + (now - startedAt).
8. A finished session's duration must remain fixed after future refreshes.
9. Do not count the same time interval twice.
10. The running display should refresh approximately once per second, but the source of truth should remain timestamps rather than incrementing a counter that drifts.
11. When the app reloads and a RUNNING session exists, define a recovery policy. Recommended: resume from stored startedAt, show a visible active timer, and permit pause/finish. Never silently reset the session.
12. Completing a task with an active session should be blocked or should finish the session through an explicit user-confirmed flow.

12. ANALYTICS AND REPORT CALCULATION RULES
======================================================================

TASK METRICS
- Total tasks = number of tasks within the selected date range.
- Completed tasks = tasks whose status is COMPLETED or completed flag is true under the current data model.
- Completion rate = completed tasks / total tasks * 100. If there are zero tasks, show 0% or a neutral no-data state; never divide by zero.
- Pending tasks = total tasks - completed tasks, excluding cancelled tasks if a cancellation status is introduced.

FOCUS TIME
- Sum each WorkSession's effective duration once.
- RUNNING session duration at present = accumulatedMs + (now - startedAt), only when startedAt is valid.
- PAUSED or FINISHED session duration = accumulatedMs.
- Historical reports should use each session's recorded start/end intervals and a documented rule for sessions that cross midnight. For reliable per-day analytics, store enough interval information to split a session across dates when required.

STREAK
- Define what counts as an active day before showing a streak. Example: at least one completed task or a minimum recorded focus duration.
- Never invent a streak when dates or historical records are missing.

REPORT
- Display selected date/range, total tasks, completed, pending, completion percentage, focus time, and reflection/evidence status.
- Clearly distinguish saved facts from calculated estimates.

13. SECURITY, PRIVACY, ACCESSIBILITY, AND RELIABILITY
======================================================================

SECURITY
- Frontend-only validation is not authentication.
- Do not store plain passwords or secrets in localStorage.
- Backend auth, if built, must hash passwords securely, verify credentials server-side, and implement appropriate session/token handling.
- Protect all user-specific data with server-side ownership checks.
- Restrict photo upload file types and file sizes; treat filenames as untrusted input.
- Never commit secret API keys or production credentials.

PRIVACY
- Explain that local prototype data remains in the browser and is not cloud-synced.
- If evidence photos are added, communicate where they are stored and how a user can remove them.
- Ask only for permissions actually needed by the feature.

ACCESSIBILITY
- Every input must have a label.
- All actions must be keyboard reachable and have clear focus styles.
- Use descriptive button names and accessible status/error messages.
- Do not rely on color alone to communicate task status.
- Respect reduced-motion preferences when adding animation.

RELIABILITY
- Preserve typed values after validation errors.
- Add loading, empty, success, and error states as appropriate.
- Prevent duplicate submissions where applicable.
- Check malformed localStorage values safely.
- Avoid setInterval leaks; always clean up timers in useEffect.
- Check edge cases: zero tasks, stale task IDs in sessions, malformed notes, reload during active session, timezone/date boundaries.
